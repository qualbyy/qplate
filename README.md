# qplate

Личный сайт в виде рабочего стола с доком и окнами. Без сборки, библиотек и внешних шрифтов: несколько файлов логики и стилей, один файл с контентом. Внутри есть конструктор, который собирает готовый сайт в папку или архивом.

Готовый пример: https://qualbyy.github.io/qplate/ — исходник: https://github.com/qualbyy/qplate
Автор скелетона: https://qualbyy.github.io

Открой `index.html` двойным кликом или запусти рядом любой статический сервер.

## что внутри

```
index.html   — пустая оболочка: место под окна и док
shell.css    — тема, окна, док, анимации, телефон
apps.css     — внутренности окон
data.js      — весь контент и список окон
apps.js      — поведение каждого типа окна
shell.js     — менеджер окон и дока
editor.css   — внешний вид конструктора
editor.js    — конструктор сайта
skills/      — скилл qplate-app: как собрать своё приложение в стиле qplate
AGENTS.md    — памятка для ИИ-агентов и разработчиков
README.md    — эта шпаргалка
assets/      — локальные картинки для галереи и плеера
```

Девять готовых окон: терминал, заметки, браузер, файлы, фотографии, плеер, настройки, документ и конструктор.

## как сделать свой сайт

1. Скопируй папку целиком:

   ```
   cp -r ~/qplate ~/мой-сайт
   ```

2. Открой `data.js` и поменяй:
   - `meta` — имя, ник, заголовок страницы, подпись;
   - `windows` — какие окна есть в доке;
   - остальные разделы — тексты, ссылки, файлы, фото, треки, страницы документа.

3. Замени `assets/photo-*.svg` и `assets/cover.svg` своими картинками (можно оставить SVG или положить PNG/JPG и поправить пути в `data.js`).

4. Проверь сайт и выложи папку на любой статический хостинг.

## как добавить своё окно

Сначала добавь запись в `windows`:

```js
{
  id: "guestbook",
  type: "guestbook",
  title: "гостевая",
  label: "гостевая",
  iconKey: "gb",
  width: 480
}
```

Потом добавь отрисовщик в `apps.js` рядом с остальными:

```js
function renderGuestbook(body, cfg, ctx) {
  const app = document.createElement("div");
  app.className = "app-page";
  app.textContent = "здесь будет гостевая книга.";
  body.appendChild(app);
}

renderers.guestbook = { render: renderGuestbook };
```

Тип окна (`type`) должен совпадать с ключом в `APP_RENDERERS`. Если ключа нет, окно покажет аккуратную заглушку.

Отрисовщик получает:

- `body` — контейнер внутри окна, клади туда разметку;
- `cfg` — запись окна из `data.js`;
- `ctx` — небольшие функции: `open`, `close`, `minimize`, `toggle`, `focus`, `center`, `applySetting`, `getSettings`, `getWindow`.

Можно вернуть объект с хуками:

```js
return {
  onOpen: function () { /* окно открыли */ },
  onHide: function () { /* окно свернули или закрыли */ }
};
```

Ну или просто навайбкодь это всё — я не запрещаю. В репозитории уже лежат `AGENTS.md` и готовый скилл в `skills/qplate-app/SKILL.md`: скорми их своему клодику или агенту, и он сделает приложение ровно по правилам qplate.

## настройки и внешний вид

- Цвета, шрифты, скругления — в начале `shell.css` в блоке `:root`.
- По умолчанию стоят: ключевой цвет «белый», тема «тёмная», обои «точки» (`data.settings` и `data.theme.accent`).
- Ключевой цвет меняется в окне настроек: пресеты из `data.theme.presets` плюс пипетка. Он перекрашивает акценты, фоны, границы и подложки по всему сайту, выбор запоминается в браузере.
- Тема: светлая, тёмная или как в системе. Тёмная строится из того же ключевого цвета, поэтому акцент остаётся узнаваемым.
- Обои рабочего стола: без обоев, точки, сетка, волны, бумага или своя картинка. Своя картинка выбирается кнопкой «выбрать файл», сжимается и хранится в браузере.
- Переключатели: анимации, подсказки дока, крупный текст, часы на столе, запоминание позиций окон. Всё это сохраняется в localStorage.
- Часы на столе показывают время и короткую дату; на телефоне и при выключенных часах скрываются.
- Позиции окон запоминаются, если включено «запоминать позиции», и не выходят за край экрана.
- Иконки приложений — SVG-строки в `data.icons`, в окне подключаются через `iconKey`.
- Скругление дока: `--dock-radius` (сейчас 20px), иконок: `--dock-icon-radius` (10px).
- Режим дока: `dockmode` — `float` (плавающий справа) или `iphone` (полоса во всю ширину снизу). Размер иконок — `docksize`, 28–64 точек.
- Стиль оболочки: `style` — `desktop`, `win98`, `aero`, `hypr` или `glass` (Liquid Glass в духе macOS 26 / iOS 26 с преломлением света через SVG-фильтр `feDisplacementMap`). Стиль меняет только форму окон и дока, ключевой цвет остаётся выбранным.
- Звуки интерфейса: ретро-щелчки окон, переключения вкладок и кнопок синтезируются через Web Audio API прямо в браузере без внешних звуковых файлов. Включаются тумблером «звуки интерфейса» в настройках.
- Блоки цитат (`quote`) оформлены светлой фоновой подложкой и контрастной вертикальной линией ключевого цвета.
- В стиле `hypr` внизу появляются подсказки `alt+1…9`; они открывают окна по порядку из `data.windows`. В полях ввода хоткеи не срабатывают.
- У окна можно поставить `pinned: true` — это «главное окно сайта». В готовом сайте останется только оно, без дока, кнопок и перетаскивания. В исходнике с конструктором режим не включается, чтобы сайт можно было редактировать.
- На телефоне док сам уменьшается и прокручивается по горизонтали, а окна открываются по одному.
- Fastfetch в терминале собирается из `data.terminal`: `ascii`, `fetchTitle`, `rows` и автоматически из `windows`. Правка — в конструкторе, вкладка «терминал». Команды — ключи `data.terminal.paths`.
- Название и иконку каждого приложения можно поменять в конструкторе, вкладка «приложения». Иконка берётся из `data.icons` или из своего файла (svg, png, jpg, webp).

## правила разметки qplate

Это правила именно этого сайта, чтобы новые окна не выбивались из оболочки. Их же можно прочитать в конструкторе на вкладке «гайд».

- **цвета** — только переменные из `shell.css`: `var(--accent)`, `var(--text)`, `var(--text-dim)`, `var(--surface-soft)`, `var(--surface-inset)`, `var(--border)`, `var(--border-dark)`, `var(--sand-dark)`, `var(--dock-bg)`. Свои hex-цвета в приложении не пишем: они не переживут смену ключевого цвета и тёмную тему.
- **шрифт** — наследуется от `body` (`--font-mono`). Новые шрифты не подключаем.
- **форма** — окно 8 px, карточки и панели 8–10 px, кнопки 6–8 px, док 20 px. Пользовательское приложение не меняет форму окна.
- **отступы** — 12, 16, 20 или 24 px. Корень приложения — `class="app-page"`, внутри отступ около 20 px.
- **кнопки** — готовые `.icon-btn`, `.setting-toggle`, `.ed-btn` или такие же по виду. Обязательны `:hover`, `:focus-visible` и `:disabled`.
- **анимации** — 0.15–0.3 с. При `body.no-motion` переходы выключаются.
- **телефон** — проверяй на 390 px. Прокрутка идёт через `.window-body`, ширина не больше 100%.
- **тёмная тема** — не хардкодить белый и чёрный фон, проверять `body.theme-dark`.
- **данные** — контент живёт в `data.js`. Отрисовщик в `apps.js` только показывает его.
- **регистрация** — `renderers.тип = { render: renderФункция }`. Ядро и `shell.js` трогать не нужно.
- **запрещено** — библиотеки, сборка, глобальные селекторы, `z-index` выше 900, инлайновые стили, новые ключи `localStorage` без префикса, заглушки `// TODO`.

Готовые классы: `.app-page`, `.content-heading`, `.empty-note`, `.icon-btn`, `.window-body`, `.setting-row`, `.file-row`. Классы `.ed-*` — только для конструктора, в готовом сайте их нет.

Пошаговый рецепт нового приложения — в `skills/qplate-app/SKILL.md`.

## конструктор

В доке есть окно «конструктор» — это редактор содержимого прямо на сайте.

Что можно менять:

- проект: название сайта, имя пользователя, имя, подпись, готовые пресеты сайта («портфолио», «блог», «плеер», «визитка») с автоматической расстановкой окон, стилей и шаблонов текста;
- заметки, документы и вкладки браузера — заголовок, текст или html, ссылки;
- файлы: дерево папок и файлов, название, текст, картинка, аудио или pdf; для медиа — путь из `assets` или файл с устройства. Открываются во встроенном просмотрщике окна «файлы»;
- фото: адрес картинки, название, подпись (кнопка «из файла» берёт картинку с устройства);
- музыка: альбом, обложка, треки;
- терминал: fastfetch (заголовок, ascii-картинка, строки «ключ — значение») и команды, их действие (текст, открыть окно, ссылка, свой javascript-код);
- настройки: какими будут тема, обои и переключатели в готовом сайте, какие цвета, темы и варианты обоев запретить, какие пункты убрать из окна настроек совсем, кнопка быстрого открытия окна настроек прямо из вкладки;
- приложения: название в доке, заголовок окна, иконка из списка или из своего файла, главное окно сайта, удалить лишнее, вернуть удалённые стандартные окна в один клик, добавить свою страницу;
- гайд: как добавить своё окно и не выбиться из оформления qplate.

Кнопки вверху:

- **применить** — показать изменения на сайте (черновик хранится в браузере);
- **сохранить сайт ▾** (выпадающее меню):
  - **в папку** — собрать отдельный сайт в выбранную папку через Chrome/Edge File System Access API;
  - **скачать zip** — скачать архив `site.zip` со всеми файлами (работает в любом браузере);
- **открыть проект** — загрузить `project.json`;
- **сбросить всё** (в разделе «проект») — вернуть исходные данные сайта, удалить черновик и кэш настроек с перезагрузкой страницы.

В собранный сайт конструктор не попадает: окно удаляется из `windows`,
а `editor.css` и `editor.js` не подключаются.

Подробная схема данных и правила правок — в `AGENTS.md`.

## как запустить

На компьютере:

```
git clone https://github.com/qualbyy/qplate.git
cd qplate
python3 -m http.server 6767
```

Если папка уже есть, хватит двух строк:

```
cd ~/qplate
python3 -m http.server 6767
```

Открыть `http://localhost:6767`. Двойной клик по `index.html` тоже работает, но сборка сайта и сохранение `site.zip` читают файлы по сети, поэтому для них нужен сервер.

## версии

Нумерация — номер сборки `ГОД.МЕСЯЦ.ДЕНЬ.СЧЁТЧИК`, например `2026.11.08.1`:
дата выхода и сколько сборок вышло за этот день. Номер не придумывается —
берётся последняя строка `CHANGELOG.md`, и счётчик прибавляется.
Совместимость старого черновика пишется в самой сборке:
`схема: без изменений` или `схема: изменилась`.
Текущая версия видна в подписи окна настроек.

Номер ставит скрипт `release.py`, руками ничего вписывать не нужно:

```
python3 release.py "что изменилось; и что ещё" --schema нет
```

он сам берёт прошлый номер, прибавляет счётчик (или начинает новый день
с `.1`), дописывает строку в `CHANGELOG.md` и меняет подпись в `apps.js`.
`--schema data.js` помечает, что схема поменялась, `--migrate "правило"`
добавляет строку про перенос черновика. `python3 release.py --check`
сверяет историю с подписью, `--undo` возвращает оба файла к состоянию
до последнего запуска.

## что упрощено намеренно

- Музыкальный плеер играет mp3, выбранный в конструкторе; без файла показывает только прогресс.
- PDF-окно листает готовые страницы из `data.js` и скачивает текст в `.txt`, а не рендерит настоящий PDF. Настоящий pdf можно добавить в окно «файлы» — там он открывается встроенным просмотрщиком браузера.
- Картинки, аудио и pdf из конструктора хранятся как data-url. Большой файл может не поместиться в черновик: конструктор предупредит, а лучше положить файл в `assets` и указать путь.
- Кнопки «назад/вперёд» в браузере ходят по открытым вкладкам, а не по интернету.
- Внешние страницы не загружаются: браузер показывает разметку из `data.js`.
